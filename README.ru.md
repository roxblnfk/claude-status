# claude-status

[![CI](https://github.com/roxblnfk/claude-status/actions/workflows/ci.yml/badge.svg)](https://github.com/roxblnfk/claude-status/actions/workflows/ci.yml)

Слежение за расходом лимитов Claude Code: иконка в трее с кольцевым
индикатором, история в SQLite и подсказка, сколько ещё можно потратить сегодня,
чтобы ровно уложиться в недельное окно.

*[English version](README.md)*

## Откуда берутся данные

Главное, что стоит знать про устройство проекта: **живых процентов лимита нет
ни в одном файле на диске.** В `~/.claude/` лежат только агрегаты
(`stats-cache.json`) и служебные файлы; текущие окна там не хранятся.

Claude Code отдаёт лимиты ровно в одном месте — на stdin команде, прописанной в
`statusLine.command`. Формат описан в
[документации](https://code.claude.com/docs/en/statusline):

```json
{
  "rate_limits": {
    "five_hour": { "used_percentage": 23.5, "resets_at": 1738425600 },
    "seven_day": { "used_percentage": 41.2, "resets_at": 1738857600 }
  }
}
```

Отсюда архитектура из двух бинарников:

| Бинарник             | Роль                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------- |
| `claude-status-hook` | Прописывается в `statusLine.command`. Разбирает JSON, пишет снимок в SQLite, печатает статусную строку. Лёгкий: запускается на каждое сообщение ассистента. |
| `claude-status`      | Окно со статистикой и иконка в трее. Читает ту же базу.                                  |

Следствия, о которых стоит помнить:

- `rate_limits` приходят только подписчикам Claude.ai (Pro/Max) и только после
  первого ответа API в сессии.
- Пока Claude Code не запущен, новых снимков нет. Это не сбой: расход в это
  время и не меняется. В окне видно возраст последнего снимка.
- Разбивку по моделям `rate_limits` не дают — она берётся из
  `~/.claude/stats-cache.json`, который Claude Code считает сам.

## Сборка и установка

Готовые архивы для Windows, macOS и Linux приложены к каждому
[релизу](https://github.com/roxblnfk/claude-status/releases). Либо собрать из
исходников:

```bash
cargo build --release
```

Оба бинарника окажутся в `target/release/` и должны лежать рядом: `claude-status`
ищет хук в своём каталоге.

Дальше — запустить `claude-status` и на вкладке **«Настройки»** нажать
**«Прописать в Claude Code»**. Там же видно текущее состояние прописки и можно
задать интервал перезапуска.

После этого перезапустите сессию Claude Code.

Прописка снимает резервную копию настроек и правит только ключ `statusLine`, не
переставляя остальные. Если там уже стоит чужая команда, кнопка предложит
заменить её: прежнее значение сохранится и вернётся при удалении хука.

То же самое из консоли, если нужна автоматизация:

```bash
./target/release/claude-status install     # прописать
./target/release/claude-status status      # проверить
```

## Команды

```
claude-status                    окно и иконка в трее
claude-status install [--interval N] [--force]
claude-status uninstall
claude-status status             состояние прописки и последний снимок
claude-status preview [шаблон]   напечатать статусную строку
```

`--interval N` (по умолчанию 60) заставляет Claude Code перезапускать хук каждые
N секунд помимо событийных обновлений — иначе во время пауз в работе снимки
перестают обновляться.

## Статусная строка

Шаблон настраивается в окне (вкладка «Настройки», там же предпросмотр, семь
готовых пресетов и список плейсхолдеров) или прямо в `config.toml`. По умолчанию:

```
{model} · ctx {ctx_pct}% · 5h {five_bar} {five_pct}% (⟳{five_reset}) · week {week_pct}% {pace}
```

Плейсхолдеры: `{model}`, `{model_id}`, `{effort}`, `{session}`, `{dir}`,
`{cost}`, `{ctx_pct}`, `{ctx_bar}`, `{five_pct}`, `{five_bar}`, `{five_reset}`,
`{five_left}`, `{week_pct}`, `{week_bar}`, `{week_reset}`, `{week_left}`,
`{opus_pct}`, `{opus_bar}`, `{pace}`, `{daily}`, `{today_left}`, `{burn}`.

Неизвестный плейсхолдер остаётся в строке дословно — так видно опечатку.

## Как считается «сколько можно тратить»

Claude Code сообщает процент окна, а не токены, поэтому весь бюджет считается в
процентах. Равномерный темп — диагональ от 0 % в начале недельного окна до 100 %
в момент сброса:

- `{daily}` — сколько процентов в сутки можно тратить, чтобы ровно уложиться в
  оставшееся время: `остаток / суток до сброса`.
- `{today_left}` — та же норма, пересчитанная на время до локальной полуночи.
- `{pace}` — отклонение от диагонали в процентных пунктах: `↑+12` означает, что
  вы опережаете график на 12 п.п.
- `{burn}` — фактический темп по крайним снимкам текущего окна, %/сутки. Окно
  определяется по `resets_at`: точки из предыдущего окна в расчёт не попадают,
  иначе сброс со 100 % на 0 % дал бы отрицательный темп.

## Локализация

Интерфейс есть на русском и английском. Язык по умолчанию берётся из системы,
переключается на вкладке «Настройки», в `config.toml`
(`[ui] language = "auto" | "en" | "ru"`) или через `CLAUDE_STATUS_LANG`, который
перекрывает и то, и другое.

Переводы лежат в одном файле [`locales/app.yml`](locales/app.yml) — оба языка
рядом, поэтому пропущенный перевод сразу заметен. Чтобы добавить язык, нужен
вариант у каждого ключа плюс запись в `Language` в `crates/core/src/i18n.rs`.

## Файлы

| Путь                                | Что это                                   |
| ----------------------------------- | ----------------------------------------- |
| `<data>/usage.sqlite3`              | снимки лимитов и дневные токены по моделям |
| `<data>/config.toml`                | настройки                                  |
| `<data>/settings.json.bak`          | резервная копия настроек Claude Code       |
| `<data>/previous-statusline.json`   | вытесненная `--force` чужая команда        |

`<data>` — `%LOCALAPPDATA%\claude-status` на Windows,
`~/.local/share/claude-status` на Linux, `~/Library/Application Support/claude-status`
на macOS. Переопределяется через `CLAUDE_STATUS_DIR`.

Снимки схлопываются: новая строка появляется, только когда изменились проценты
или границы окон, причём сравнение идёт в пределах одной сессии, — иначе хук на
каждом сообщении плодил бы дубликаты. Хранятся 180 дней (настраивается, `0` —
вечно), кнопка **Настройки → Хранение → Сбросить статистику** удаляет их.

## Несколько сессий одновременно

Каждая запущенная сессия Claude Code пишет свои показания, а простаивающая
повторяет снимок, снятый когда-то давно, — поэтому самая свежая строка не
означает самые свежие данные. Внутри одного окна (`resets_at` совпадает) расход
только растёт, значит актуально максимальное значение, а не последнее. Тот же
бегущий максимум рисует график истории: сырые строки скакали бы между реальной
цифрой и устаревшей.

## Переменные окружения

| Переменная            | Назначение                                          |
| --------------------- | --------------------------------------------------- |
| `CLAUDE_CONFIG_DIR`   | каталог Claude Code вместо `~/.claude`              |
| `CLAUDE_STATUS_DIR`   | каталог с базой и конфигом                          |
| `CLAUDE_STATUS_DUMP`  | файл, куда хук дописывает сырой JSON от Claude Code |
| `CLAUDE_STATUS_LANG`  | язык интерфейса: `en`, `ru` или `auto`              |
| `CLAUDE_STATUS_DEBUG` | печатать ошибки хука в stderr                       |

`CLAUDE_STATUS_DUMP` полезен, когда схема statusline расширяется: недельное окно
Opus, например, документацией до сих пор не описано, хотя в `/usage` показывается
отдельной полосой. Код его читает, если оно придёт.

## Платформы

Windows и macOS работают из коробки. На Linux трею нужны системные библиотеки:

```bash
sudo apt install libgtk-3-dev libayatana-appindicator3-dev
```

Иконка там живёт поверх libayatana-appindicator и требует главного цикла GTK,
которого у winit нет, — он прокручивается вручную из цикла отрисовки. Проверено
только на Windows.

## Разработка

```bash
cargo test --workspace
cargo clippy --workspace --all-targets
```

Хук можно прогнать вручную, не трогая настоящие настройки:

```bash
echo '{"model":{"display_name":"Opus"},"rate_limits":{"five_hour":{"used_percentage":52,"resets_at":1800000000}}}' \
  | CLAUDE_STATUS_DIR=/tmp/cs-test ./target/debug/claude-status-hook
```

`CLAUDE_CONFIG_DIR` позволяет так же безопасно проверять `install`/`uninstall` на
временном каталоге.

### Релизы

Сообщения коммитов следуют [Conventional Commits](https://www.conventionalcommits.org/):
`feat:` поднимает минорную версию, `fix:` — патч, остальное в changelog не
попадает. [release-please](https://github.com/googleapis/release-please) держит
открытым pull request со следующей версией и накопленным changelog; его слияние
проставляет тег и собирает бинарники под все платформы.

Версия хранится в `version.txt` и в `Cargo.toml` (строка с пометкой
`x-release-please-version`) — оба обновляются этим pull request'ом, править их
руками не нужно.
