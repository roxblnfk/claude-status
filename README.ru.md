# claude-status

[![CI](https://img.shields.io/github/actions/workflow/status/roxblnfk/claude-status/ci.yml?branch=master&style=flat-square&label=CI&logo=github)](https://github.com/roxblnfk/claude-status/actions/workflows/ci.yml)
![Vibe Index](https://img.shields.io/badge/Indexing%20Vibe-6168e5?style=flat-square)

Слежение за расходом лимитов Claude Code: иконка в трее с двумя кольцевыми
индикаторами — лимит сессии и норма на сегодня, — история в SQLite и подсказка,
сколько ещё можно потратить сегодня, чтобы ровно уложиться в недельное окно.

*[English version](README.md)*

## Откуда берутся данные

Главное, что стоит знать про устройство проекта: **живых процентов лимита нет
ни в одном файле на диске.** В `~/.claude/` лежат только агрегаты
(`stats-cache.json`) и служебные файлы; текущие окна там не хранятся.

Claude Code отдаёт лимиты ровно в одном месте — на stdin команде, прописанной в
`statusLine.command`. Формат описан в
[документации](https://code.claude.com/docs/en/statusline):

```json
{
  "rate_limits": {
    "five_hour": { "used_percentage": 23.5, "resets_at": 1738425600 },
    "seven_day": { "used_percentage": 41.2, "resets_at": 1738857600 }
  }
}
```

Эту команду запускает только Claude Code, стартовавший из терминала. Сессия,
поднятая редактором через agent SDK — например, панель агента в Zed, — статусную
строку не рисует, и хук там не срабатывает ни разу. Для таких случаев и для
долгих пауз есть [прямой запрос к Claude Code](#прямой-запрос-к-claude-code).

Поэтому один бинарник работает в двух ролях:

| Запуск               | Роль                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------- |
| `claude-status hook` | Прописывается в `statusLine.command`. Разбирает JSON, пишет снимок в SQLite, печатает статусную строку. Запускается на каждое сообщение ассистента. |
| `claude-status`      | Окно со статистикой и иконка в трее. Читает ту же базу.                                  |

Раньше хук был отдельным бинарником, чтобы статусная строка не платила за
загрузку всего окна. Теперь в архиве один файл, а экономия достигается
отложенной загрузкой: графические библиотеки окна резолвятся при первом
обращении, а не на старте процесса, как это делает таблица импорта. Замер на
Windows: **14.8 мс** с отложенной загрузкой против **79 мс** без неё, при
**13.3 мс** у отдельного бинарника. Вся разница была именно в этом.

Следствия, о которых стоит помнить:

- `rate_limits` приходят только подписчикам Claude.ai (Pro/Max) и только после
  первого ответа API в сессии.
- Пока Claude Code не запущен, новых снимков нет. Это не сбой: расход в это
  время и не меняется. В окне видно возраст последнего снимка.
- Если пауза оказалась длиннее самого окна, последний снимок описывает окно,
  которое с тех пор сбросилось. Такая цифра не выдаётся за текущую: шкала
  остаётся пустой, а значение приводится отдельно как последнее известное.
- Разбивку по моделям `rate_limits` не дают — она берётся из
  `~/.claude/stats-cache.json`, который Claude Code считает сам, а недельный
  лимит по отдельной модели — только из прямого запроса ниже.

## Прямой запрос к Claude Code

Claude Code отвечает на управляющий запрос теми же данными, что показывает на
экране `/usage`. В agent SDK это метод
`usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET()`, а на проводе —
одна строка в stdin:

```bash
echo '{"type":"control_request","request_id":"r","request":{"subtype":"get_usage"}}' \
  | claude --print --input-format stream-json --output-format stream-json
```

В ответе — пятичасовое и недельное окна, недельный лимит, привязанный к одной
модели (в статусной строке его нет вовсе), и кредиты сверх лимита. Данные
привязаны к аккаунту, поэтому спрашивать можно любой экземпляр — не обязательно
ту сессию, которая тратила.

Цена, по замерам: **3.3–4.2 с** и около **390 МБ** на время вызова, порядка 1.2 с
процессорного времени. Токены не тратятся — в ответе `total_cost_usd: 0` и
нулевое время API, — но сам Claude Code делает один запрос за цифрами, и на
каждый вызов отрабатывают хуки `SessionStart`.

Поэтому дешёвый источник имеет приоритет. Запрос делается, только если сошлось
всё сразу:

- он включён (`[probe] enabled`, по умолчанию да);
- с прошлого прошло `interval_secs` (по умолчанию 15 минут, меньше 5 нельзя —
  таким же дросселем Claude Code защищает собственный кэш расхода);
- и собранные снимки перестали быть полезными: их нет вовсе, нет свежее
  `fresh_secs`, либо последний описывает уже сброшенное окно.

Пока статусная строка присылает данные, запрос не делается вообще.
`claude-status probe` выполняет его принудительно, в **«Настройки → Источник
данных»** есть кнопка. `CLAUDE_STATUS_CLAUDE_BIN` указывает на исполняемый файл, если он лежит
не там, куда его кладёт нативный установщик.

API помечен в SDK как нестабильный и может измениться без предупреждения;
неудачный запрос показывается сообщением и в остальном игнорируется.

## Сборка и установка

Готовые архивы для Windows, macOS и Linux приложены к каждому
[релизу](https://github.com/roxblnfk/claude-status/releases). Либо собрать из
исходников:

```bash
cargo build --release
```

Единственный `claude-status` окажется в `target/release/` и может лежать где
угодно — прописка запоминает путь, по которому он был.

Дальше — запустить `claude-status` и на вкладке **«Настройки»** нажать
**«Прописать в Claude Code»**. Там же видно текущее состояние прописки и можно
задать интервал перезапуска.

После этого перезапустите сессию Claude Code.

Прописка снимает резервную копию настроек и правит только ключ `statusLine`, не
переставляя остальные. Если там уже стоит чужая команда, кнопка предложит
заменить её: прежнее значение сохранится и вернётся при удалении хука.

То же самое из консоли, если нужна автоматизация:

```bash
./target/release/claude-status install     # прописать
./target/release/claude-status status      # проверить
```

## Команды

```
claude-status                    окно и иконка в трее
claude-status --tray             сразу в трей, без окна
claude-status install [--interval N] [--force]
claude-status uninstall
claude-status status             состояние прописки и последний снимок
claude-status preview [шаблон]   напечатать статусную строку
claude-status probe              спросить лимиты у Claude Code и сохранить
claude-status update             скачать с GitHub новую версию, если она есть
claude-status hook               прочитать порцию данных со stdin (это запускает Claude Code)
```

Если бинарник переместить или переименовать, прописка останется указывать на
старое место. Это так и показывается — на вкладке **«Настройки»** и в `status`,
— а не выдаётся за рабочее состояние; повторная прописка чинит. То же самое с
установкой, сделанной релизом, где ещё был отдельный `claude-status-hook`.

`--interval N` (по умолчанию 60) заставляет Claude Code перезапускать хук каждые
N секунд помимо событийных обновлений — иначе во время пауз в работе снимки
перестают обновляться.

## Статусная строка

Шаблон настраивается в окне (**«Настройки → Статусная строка»**, там же
предпросмотр, семь готовых пресетов и список плейсхолдеров) или прямо в
`config.toml`. По умолчанию:

```
{model} · ctx {ctx_pct}% · 5h {five_bar} {five_pct}% (⟳{five_reset}) · week {week_pct}% {pace}
```

Плейсхолдеры: `{model}`, `{model_id}`, `{effort}`, `{session}`, `{dir}`,
`{cost}`, `{ctx_pct}`, `{ctx_bar}`, `{five_pct}`, `{five_bar}`, `{five_reset}`,
`{five_left}`, `{week_pct}`, `{week_bar}`, `{week_reset}`, `{week_left}`,
`{opus_pct}`, `{opus_bar}`, `{pace}`, `{daily}`, `{today_left}`, `{burn}`.

Неизвестный плейсхолдер остаётся в строке дословно — так видно опечатку.

## Как считается «сколько можно тратить»

Claude Code сообщает процент окна, а не токены, поэтому весь бюджет считается в
процентах. Равномерный темп — диагональ от 0 % в начале недельного окна до 100 %
в момент сброса:

- `{daily}` — сколько процентов в сутки можно тратить, чтобы ровно уложиться в
  оставшееся время: `остаток / суток до сброса`.
- `{today_left}` — сколько осталось от нормы на сегодня (см. ниже).
- `{pace}` — отклонение от диагонали в процентных пунктах: `↑+12` означает, что
  вы опережаете график на 12 п.п.
- `{burn}` — фактический темп, %/сутки, усреднённый от первого снимка текущего
  окна до последнего момента, когда свежий снимок ещё подтверждался. Паузы
  входят в счёт: процентный пункт, набранный за четыре минуты и потом
  простоявший два часа, — это 11 %/сутки, а не 350. Окно определяется по
  `resets_at`: точки из предыдущего окна в расчёт не попадают, иначе сброс со
  100 % на 0 % дал бы отрицательный темп. Меньше получаса наблюдений — темпа
  нет вовсе: Claude Code отдаёт целые проценты, и один процент за несколько
  минут экстраполируется в бессмыслицу.

## Норма на сегодня

Дневного окна у Claude Code нет, поэтому оно выкраивается из недельного.

День отсчитывается от уровня, на котором неделя стояла в локальную полночь, —
это наибольший снимок, записанный до неё. Норма на сегодня — то, что оставалось
в тот момент, делённое на число ещё предстоящих суток; дальше она на день
фиксируется. Норма, пересчитываемая по мере трат, отступала бы и никогда не была
бы достигнута. В последний день недели деление отменяется: сегодня можно
потратить весь остаток.

Из-за этого норма на сегодня и `{daily}` — разные числа, и так задумано:
`{daily}` — то же деление, но заново с каждым снимком и по времени, оставшемуся
*от сейчас*, поэтому оно растёт, когда день прошёл экономно. Норма на сегодня
зафиксирована в полночь и не двигается. Первое отвечает на вопрос «с какой
скоростью дотянуть до сброса», второе — «сколько отведено на сегодня».

Если сбор данных начался позже, чем неделя, снимка до полуночи нет, и уровень
приходится оценивать: расход из первого снимка равномерно раскладывается назад
по прошедшим дням недели. Строка **Сегодня** в окне помечается, когда цифра
опирается на такую оценку.

## Иконка в трее

Два концентрических индикатора, внешний вписан в границы иконки:

| Кольцо    | Что показывает                                        |
| --------- | ----------------------------------------------------- |
| внешнее   | пятичасовой лимит сессии                              |
| внутреннее| сколько израсходовано от нормы на сегодня; сверх 100 % упирается в полный круг |

У обоих остаётся дорожка, поэтому кольцо остаётся кольцом при любом заполнении и
иконка никогда не превращается в сплошной круг. Цвет следует уровню: зелёный,
жёлтый после половины, оранжевый после трёх четвертей, красный после 90 %.

## Запуск вместе с системой

**Настройки → Приложение → Автозапуск** прописывает программу в операционной системе:
значение в `HKCU\...\CurrentVersion\Run` на Windows, файл `.desktop` в
`~/.config/autostart` на Linux, агент запуска в `~/Library/LaunchAgents` на
macOS. В записи стоит `--tray`, поэтому при входе в систему появляется иконка,
а окно — нет.

Галочка не хранится в `config.toml` — её состояние читается из операционной
системы при каждом обновлении. Своя копия ответа устарела бы в тот момент,
когда запись удалит что-нибудь ещё. Если прописанный путь ведёт к другому
бинарнику — так бывает после переноса файла — на экране настроек об этом
написано, а не показано «автозапуск выключен».

## Обновление

**Настройки → Обновление** — одна кнопка на весь путь: сначала предлагает
проверить, потом загрузить найденное, потом перезапуститься в новую версию.
Загруженный файл заменяет текущий там, где он лежит, — перекладывать и
прописывать заново ничего не нужно. Вручную только проверка: до нажатия кнопки в
сеть ничего не уходит. Из консоли то же самое делает `claude-status update`.

Каждый релиз кладёт рядом с архивами голый исполняемый файл — качается именно
он: распаковывать нечего, поэтому и поддержки архивных форматов внутри
приложения нет. Нужный файл выбирается по триплету цели в имени, записанному при
сборке.

Загруженное сверяется с размером, который называет GitHub, и с сигнатурой
исполняемого файла — до того, как что-либо трогается на диске. Это ловит прокси,
ответивший страницей с ошибкой. Дальше работающий бинарник отодвигается
переименованием, а новый встаёт на его место, так что путь в
`statusLine.command` продолжает работать; отодвинутый файл удаляется при
следующем запуске. Если переезд сорвётся, старый бинарник возвращается назад.

## Локализация

Интерфейс есть на русском и английском. Язык по умолчанию берётся из системы,
переключается на вкладке «Настройки», в `config.toml`
(`[ui] language = "auto" | "en" | "ru"`) или через `CLAUDE_STATUS_LANG`, который
перекрывает и то, и другое.

Переводы лежат в одном файле [`locales/app.yml`](locales/app.yml) — оба языка
рядом, поэтому пропущенный перевод сразу заметен. Чтобы добавить язык, нужен
вариант у каждого ключа плюс запись в `Language` в `crates/core/src/i18n.rs`.

## Файлы

| Путь                                | Что это                                   |
| ----------------------------------- | ----------------------------------------- |
| `<data>/usage.sqlite3`              | снимки лимитов и дневные токены по моделям |
| `<data>/config.toml`                | настройки                                  |
| `<data>/settings.json.bak`          | резервная копия настроек Claude Code       |
| `<data>/previous-statusline.json`   | вытесненная `--force` чужая команда        |

`<data>` — `%LOCALAPPDATA%\claude-status` на Windows,
`~/.local/share/claude-status` на Linux, `~/Library/Application Support/claude-status`
на macOS. Переопределяется через `CLAUDE_STATUS_DIR`.

Снимки схлопываются: новая строка появляется, только когда изменились проценты
или границы окон, причём сравнение идёт в пределах одной сессии, — иначе хук на
каждом сообщении плодил бы дубликаты. Хранятся 180 дней (настраивается, `0` —
вечно), кнопка **Настройки → Приложение → Сбросить статистику** удаляет их.

## Несколько сессий одновременно

Каждая запущенная сессия Claude Code пишет свои показания, а простаивающая
повторяет снимок, снятый когда-то давно, — поэтому самая свежая строка не
означает самые свежие данные. Внутри одного окна (`resets_at` совпадает) расход
только растёт, значит актуально максимальное значение, а не последнее. Тот же
бегущий максимум рисует график истории: сырые строки скакали бы между реальной
цифрой и устаревшей.

## Переменные окружения

| Переменная            | Назначение                                          |
| --------------------- | --------------------------------------------------- |
| `CLAUDE_CONFIG_DIR`   | каталог Claude Code вместо `~/.claude`              |
| `CLAUDE_STATUS_DIR`   | каталог с базой и конфигом                          |
| `CLAUDE_STATUS_DUMP`  | файл, куда хук дописывает сырой JSON от Claude Code |
| `CLAUDE_STATUS_LANG`  | язык интерфейса: `en`, `ru` или `auto`              |
| `CLAUDE_STATUS_DEBUG` | печатать ошибки хука в stderr                       |

`CLAUDE_STATUS_DUMP` полезен, когда схема statusline расширяется: недельное окно
Opus, например, документацией до сих пор не описано, хотя в `/usage` показывается
отдельной полосой. Код его читает, если оно придёт.

## Платформы

Windows и macOS работают из коробки. На Linux трею нужны системные библиотеки:

```bash
sudo apt install libgtk-3-dev libayatana-appindicator3-dev libxdo-dev
```

Иконка там живёт поверх libayatana-appindicator и требует главного цикла GTK,
которого у winit нет, — он прокручивается вручную из цикла отрисовки. Проверено
только на Windows.

## Разработка

```bash
cargo test --workspace
cargo clippy --workspace --all-targets
```

Хук можно прогнать вручную, не трогая настоящие настройки:

```bash
echo '{"model":{"display_name":"Opus"},"rate_limits":{"five_hour":{"used_percentage":52,"resets_at":1800000000}}}' \
  | CLAUDE_STATUS_DIR=/tmp/cs-test ./target/debug/claude-status hook
```

`CLAUDE_CONFIG_DIR` позволяет так же безопасно проверять `install`/`uninstall` на
временном каталоге.

### Релизы

Сообщения коммитов следуют [Conventional Commits](https://www.conventionalcommits.org/):
`feat:` поднимает минорную версию, `fix:` — патч, остальное в changelog не
попадает. [release-please](https://github.com/googleapis/release-please) держит
открытым pull request со следующей версией и накопленным changelog; его слияние
проставляет тег и собирает бинарники под все платформы.

Версия хранится в `version.txt` и в `Cargo.toml` (строка с пометкой
`x-release-please-version`) — оба обновляются этим pull request'ом, править их
руками не нужно.

Тем же pull request'ом обновляется бейдж [Vibe
Index](https://github.com/roxblnfk/action-vibe-index) — доля истории,
написанной ИИ, а не руками. Он пересчитывается в ветку релиза, а не в `master`,
чтобы цифра приезжала вместе с релизом, который её описывает, а не менялась на
каждый push.
